Geodesic interpolations of reaction pathways
====
Constructing interpolation paths between molecular geometries to obtain reaction path.

Traditional interpolation methods encounter difficulty when it comes to redundant internal coordinate spaces, because the feasible physical space compose only a very small and highly curved subspace.  In this method, we avoid the problem of feasibility by operating strictly in feasible space, and bring in the benefit of internal coordinates through proper application of the corresponding metric tensor.  With this new formulation, we view the configuration space as a Riemannian manifold with a metric generated from a set of internal coordinates. The interpolation paths are defined as geodesic curves on such manifolds.  In other words the integrated total coordinate change is minimized. Such a definition ensures that the constructed paths are smooth and well behaved. The package is also used for smoothing discontinuous or noisy trajectories obtained from MD simulations.

It has been shown that the method generate smooth paths with reasonable barrier height even for highly complex reactions, such as protein unfolding or concerted cycloaddition reactions with many simutaneous ring formations.   The default coordinate system uses Morse scaled pair-wise distances.  The lengths in such coordinate systems have the physical meaning of the total number of bond changes along the path.

This is a pure python implementation, so it is not optimized for speed, but rather is intended to serve as a reference implementation of the algorithms described in the paper.  Still, interpolating systems with ~1000 atoms should not be a problem.


Directory Structure
----
- geodesic_interpolate      Python package for interpolation and smoothing by finding geodesic curves with redundant internal metrics
  - `__init__.py`      Python package file
  - `__main__.py`      Standalone script for performing interpolation and smoothings.
  - `geodesic.py`      Computation and minimization of path length in redundant internal metrics.  This is used to optimize
   a path way to find a geodesic.  Cannot change the number of images during optimization
  - `interpolation.py` Generating approximate interpolation points to be used as starting guess for the geodesic optimizations.
   Recursively attempt to perform bisections on largest segment in internal space.  Generally will create path
   with discontinuities, so a smoothing process need to follow this.
  - `coord_utils.py`   Coordinate utilities.  A simplified version of Nanoreactor coordinates module which provide a scaled
   interatomic distance coordinate, pair screening based on threshold and connectivity, as well as trans-rotational
   alignment based on Kabsch algorithm.
  - `analysis.py`      Quality checks of interpolated paths (torn bonds, close contacts, bonds crossing)
  - `fileio.py`        XYZ file reading and writing, and reading/writing periodic structures through ASE
  - `pbc.py`           Periodic boundary condition utilities: cell handling, minimum image convention, path unwrapping
   and periodic neighbor search
  - `ase_interface.py` Interpolation of lists of `ase.Atoms`
- examples             `make_gifs.py`: example interpolations (periodic and molecular) rendered as GIFs with AtomsPlotter
- tests                Unit tests (`python -m pytest tests`), including periodic systems, fixed atoms and the path checks
- setup.py             Installation script.  This will install both the Python package, which can be imported by name `geodesic_interpolate`
   and the standalone script, which is also named `geodesic_interpolate`
- test_cases           A few test cases used to check the performance of the code.  Note that the large ones may take a few minutes
   thanks to Python.  Especially need to run them when testing out alternative coordinate scaling methods.
  - `H+CH4_CH3+H2.xyz` A simple test case.  Should always work
  - `DielsAlder.xyz`   Dehydro-Diels-Alder reaction.  This is an important test case because the initial structure is planar symmetric and
   could access both the final structure and its mirror image, which as exactly the same internal coordinates.  Proper
   monitoring of geodesic length during the interpolation process is therefore crucial for this to work, without which
   the raw interpolated path will jump between mirror images and the optimized path would contain some flopping.
   Also tests the non-sweeping global path optimization algo in a relatively large system.
  - `TrpCage_unfold.xyz` Unfolding a Trp-cage mini-protein.  Need at least 10 images to work.  Folded geometry taken from Stefan''s test
   directory which is instead taken from Nathan.  Unfolded structure is generated by force navigated MD for 1ns under
   1nN on C and N terminal with ReaxFF, then optimizing without force at 6-31g/b3lyp level.  For testing many
   simultaneous large amplitude motions.
  - `collagen.xyz`     Interpolate between the solution and crystal structure of collagen Kunitz domain 1kun - 1kth.  Solvents removed
   from the PDB structures.  Tests collision avoidance for large movements in the core of folded protein.  Other
   groups should slightly breath to create room for the part that changes.
  - `calcium_binding.xyz`  Binding two Ca2+ ions to the yeast Calmodulin N terminal domain 1f54 -1f55.  The apo structure did not have
   ions so two of which were added by hand at random locations away from the protein.  It seem to be hard to avoid
   large movements of the Ca2+ cations when they are very far away from the protein but once in contact they should
   move smoothly.  This is to test if the interpolater can correctly route and find the entry point and connect the
   path.

Installation
----

### From PyPI

Once a release has been published to PyPI, install the package with:

    pip install geodesic_interpolate

### From Source

The package can be used without installation from the package directory with

    python -m geodesic_interpolate filename ...

To use the script from an arbitrary location or import the Python module, install the package with pip:

    python -m pip install .

This will install a Python package `geodesic_interpolate` and two standalone scripts: `geodesic_interpolate` and
`geodesic_analyze` (checks existing paths, see below).  Use `python -m pip install -e .` for an editable install;
after updating an existing installation, reinstall so that new scripts are created.  Without installation, the path
checks are run with `python -m geodesic_interpolate.analysis band.traj`.
The package can be invoked from an arbitrary location using the aforementioned command line after installation,
and a standalone script with the same signature can also be used

    geodesic_interpolate filename.xyz --output output.traj --nimages 20 ...


Periodic systems and ASE
----
Periodic boundary conditions are supported for bulk, slab (2D) and wire (1D) systems.  Lists of
[ASE](https://wiki.fysik.dtu.dk/ase/) `Atoms` can be interpolated directly; the cell, `pbc` flags and
constraints are taken from the images:

    from ase.io import read
    from ase.mep import NEB
    from geodesic_interpolate import interpolate

    images = interpolate([read('initial.traj'), read('final.traj')], nimages=9)
    neb = NEB(images)

The command line script reads any format ASE understands (XYZ, extended XYZ, POSCAR/CONTCAR, CIF, traj,
...), also from several files, and writes an ASE trajectory by default.  `--vasp` additionally writes the
image folders of a VASP NEB calculation (`00/POSCAR` ... `NN/POSCAR`, with selective dynamics):

    geodesic_interpolate POSCAR_initial POSCAR_final --nimages 9 --vasp neb

The lower level API takes `cell` (lattice vectors as rows), `pbc` and `fixed` arguments, e.g.
`Geodesic(symbols, path, cell=cell, pbc=[True, True, False], fixed=[0, 1, 2])` and
`redistribute(..., cell=cell, pbc=pbc, fixed=fixed)`.

How it works:
  - Atoms may be wrapped differently in each image.  The path is first unwrapped: bonds present in both
    images (1.2 times the sum of covalent radii) keep their periodic image, and every bonded fragment is
    translated as a whole by the lattice vector that minimizes its displacement.  Atoms without such bonds
    follow the minimum image convention (MIC).  Fragments may therefore move by more than half a lattice
    vector (e.g. a chain end passing through the cell boundary), while isolated atoms must move less.
  - The output path is unwrapped so that atoms move continuously; use `wrap=True` (`--wrap`) to wrap atoms
    back into the cell.  `use_pbc=False` (`--no-pbc`) ignores the cell.
  - Each internal coordinate is the distance between atom `i` and a fixed periodic image `j + n` of atom
    `j`, stored as `(i, j, n1, n2, n3)`.  The lattice translations `n` are found by a periodic neighbor search
    and kept fixed during the optimization, so coordinates stay smooth when atoms cross the cell boundary.
    Small cells, where an atom interacts with several images of the same neighbor, are handled correctly.
  - No rotational or translational alignment is performed, so atoms that do not move (e.g. fixed slab
    layers) stay in place.  The cell must be the same for all images.

Fixed atoms:
  - `FixAtoms`, `FixCartesian` and `FixScaled` (selective dynamics of POSCAR files, when the fixed directions
    are Cartesian axes) constraints are enforced for coordinates fixed in *all* input images, as are atoms given
    with `--fix 0-17 20` or `fixed=`.  Fixed coordinates are removed from the optimization and never change.
    With fixed atoms, rigid-body alignment of molecules is disabled as well.
  - Coordinates fixed in only some input images, e.g. atoms pinned to relax a constrained end point, move freely
    along the path.  The end points of the output keep their own constraints; interior images get the common ones.

Covalent radii, used for the reference distances of the scaled coordinates, are taken from `ase.data`
(Cordero et al., Dalton Trans. 2008, 2832), so all elements are covered.

`examples/make_gifs.py` runs a few example interpolations (vacancy hop in Al, H on Cu(111) with fixed bottom
layers, and two of the molecular test cases) and renders them as GIFs with
[AtomsPlotter](https://doi.org/10.5281/zenodo.23316072).

Smoothing and reproducibility:
  - After smoothing, all images are checked for atom pairs closer than `--dist-cutoff` that are not part of the
    coordinate system (e.g. a molecule pushed into a surface or through itself).  These are added and the path is
    smoothed again, up to `--max-rounds` times (`max_rounds=`, default 5).
  - The bisection uses random nudges.  `--seed` (`seed=`) makes runs reproducible; results also depend on the
    number of BLAS threads (`OMP_NUM_THREADS`).
  - `--scaling` now sets the Morse alpha; previously it was ignored and 1.7 was always used.

Checking paths and running several seeds:
  - For large-amplitude motions (e.g. a ring opening where a chain end swings over the molecule) the random nudges
    of the bisection can decide between a valid path and one with torn bonds or parts of a molecule passing through
    each other.  `geodesic_interpolate ... --seeds 0 1 2 3 --jobs 4` runs every seed, checks each path, prints a
    report and keeps the shortest path passing all checks (`--keep-all` also writes `<output>_seed<SEED>.<ext>`).
    If no seed passes, the best one is written anyway and the command exits with status 2.  In Python:

        band, report = interpolate(images, nimages=33, seeds=[0, 1, 2, 3], jobs=4,
                                   thresholds=dict(contact=0.4), return_report=True)

    `report` lists every seed (best first) with its `quality` (the metrics below) and `failed` checks.  If no seed
    passes, a warning is logged and the best path is returned.  `thresholds` overrides individual limits.
  - The checks (`geodesic_interpolate.analysis`, also `geodesic_analyze band.traj ...` or `--analyze` for a single
    run) are:
      - `stretch`: largest ratio of a bond present in both end points to its end-point length, on the unwrapped
        positions (a periodic-image error shows up as a bond across the box).  Fails above 1.3.
      - `contact`: smallest ratio of the distance between atoms more than three bonds apart to the smaller of the
        sum of their van der Waals radii (Alvarez) and their distance in the end points.  Fails below 0.5.
      - `crossing`: smallest distance between points along two bonds of a molecule that share no atom, on sub-steps
        between images.  Atom-atom distances can stay normal while two bonds pass through each other, so this is
        checked separately.  Fails below 0.8 A.
  - The limits are adjustable (`geodesic_analyze --stretch --contact --crossing`, `thresholds=` in Python).  The
    van der Waals radii of metals are large, so a close but harmless approach of an adsorbate atom to a surface
    can score as low as about 0.6 on `contact`.
  - Bonds are described by saturating Morse-scaled distances, so a strongly curved path can still stretch a bond
    that exists in both end points.  Check bond lengths along large-amplitude paths.


Usage
----
usage: geodesic_interpolate [-h] [--nimages NIMAGES] [--sweep] [--no-sweep]
                            [--output OUTPUT] [--tol TOL] [--maxiter MAXITER]
                            [--microiter MICROITER] [--scaling SCALING]
                            [--friction FRICTION] [--dist-cutoff DIST_CUTOFF]
                            [--logging {DEBUG,INFO,WARNING,ERROR}]
                            [--save-raw SAVE_RAW] [--vasp [DIR]] [--max-rounds MAX_ROUNDS] [--seed SEED]
                            [--seeds SEED [SEED ...]] [--jobs JOBS] [--keep-all] [--analyze]
                            [--fix INDEX [INDEX ...]] [--no-pbc] [--wrap]
                            filename [filename ...]

Interpolates between two geometries

positional arguments:
  * filename            File(s) containing geometries in any format ASE can read. If the number of images is smaller than
   the desired number, interpolation points will be added. If the number is greater, subsampling will be performed.
   Cell and periodic boundary conditions of the first image are used; coordinates fixed in all images stay fixed.

optional arguments:
  * `-h`, `--help`      show this help message and exit
  * `--nimages NIMAGES` Number of images. (default: 17)
  * `--sweep`           Sweep across the path optimizing one image at a time, instead of moving all images at the same time.
   Default is to perform sweeping updates if there are more than 30 atoms. (default: None)
  * `--no-sweep`        Do not perform sweeping. (default: None)
  * `--output OUTPUT`   Output filename.  The format is determined by ASE from the extension. (default: interpolated.traj)
  * `--vasp [DIR]`      Also write VASP NEB input, DIR/00/POSCAR ... DIR/NN/POSCAR.  DIR defaults to the current directory.
  * `--fix INDEX ...`   Indices of atoms to keep fixed in addition to the constraints in the input, e.g. `--fix 0-15 20`.
  * `--tol TOL`         Convergence tolerance (default: 0.002)
  * `--maxiter MAXITER` Maximum number of minimization iterations (default: 15)
  * `--microiter MICROITER`  Maximum number of micro iterations for sweeping algorithm. (default: 20)
  * `--scaling SCALING` Exponential parameter for morse potential (default: 1.7)
  * `--friction FRICTION`   Size of friction term used to prevent very large change of geometry. (default: 0.01)
  * `--dist-cutoff DIST_CUTOFF` Cut-off value for the distance between a pair of atoms to be included in the coordinate system. (default: 3)
  * `--logging {DEBUG,INFO,WARNING,ERROR}`   Logging level to adopt [ DEBUG | INFO | WARNING | ERROR ] (default: INFO)
  * `--save-raw SAVE_RAW`   When specified, save the raw path after bisections be before smoothing. (default: None)
  * `--max-rounds MAX_ROUNDS`  Maximum number of smoothing rounds; atom pairs that came into contact without being
   coordinates are added after each round. 1 smooths only once. (default: 5)
  * `--seed SEED`       Random seed for reproducible results. Results also depend on the number of BLAS threads.
  * `--seeds SEED ...`  Run several seeds, check each path, print a report and keep the shortest valid one.
  * `--jobs JOBS`       Number of parallel processes for `--seeds`. (default: 1)
  * `--keep-all`        With `--seeds`, also write the path of every seed.
  * `--analyze`         Check the final path and print the report.
  * `--no-pbc`          Ignore the cell of periodic input files and treat the system as a molecule.
  * `--wrap`            Wrap atoms back into the cell in the output.  By default periodic paths are written unwrapped
   so that atoms move continuously.
